# 運転環境認識（試作）

車内にスマホを固定し、背面カメラの映像と GPS 速度を表示し、前方の道路環境を認識する Web アプリ（PWA）です。
研究・試作用で、**安全装置ではありません**。

## 現在の段階

| 段階 | 内容 | 状態 |
|---|---|---|
| ステップ1 | カメラ映像・GPS 速度・メーター画面 | 完了（iPhone 実機で確認済み） |
| ステップ2 | 車線認識 | 実装済み。実機で走行テスト中（横向き・黄色い線に対応） |
| ステップ3 | 道路標識認識 | **中止**（下の「標識認識をやめた理由」を参照） |
| ステップ4 | 人（歩行者）の検出 | **最優先**。未実装 |
| ステップ5 | 人の危険判定と警告 | 未実装 |
| （保留） | 横断歩道認識 | 未実装。人の検出の後で考える |

## できること

- 背面カメラの映像を背景に表示
- GPS による現在速度の表示（取得できないときは `--` と理由。0 とは区別）
- 画面の自動消灯の防止（Wake Lock API）
- **車線の認識**: 白線らしい線を探して、左右の境界を映像に重ねて表示
- **車線内の位置**: 左右の境界の間のどこにいるかを表示（「中央合わせ」で基準を設定した後）
- 横断歩道・歩行者の表示欄（**どちらも「未確認」。認識は未実装**）
- カメラ・GPS・常時点灯・処理（fps）の状態を画面下に表示
- カメラが使えない場合の理由表示と再試行

## 認識結果の 3 つの状態

| 状態 | 画面の表示 | 意味 |
|---|---|---|
| 検出 | 水色の塗りつぶし | 検出できた |
| 検出されず | 白い枠 | 映像は確認できたが検出されなかった（**「ない」「安全」という意味ではありません**） |
| 未確認 | 橙の点線＋斜線 | 確認できていない（未実装・映像なし・暗すぎる・処理停止） |

処理が止まったときは、前回の結果を残さず「未確認」に戻します。
車線は、映像が暗すぎて判定できないときも「検出されず」ではなく「未確認」にします。

## 車線認識のしくみ

1. 道路が写る帯だけを見ます。ダッシュボードや空は見ません（縦向き: 画面の高さ 40〜53.5%、横向き: 45〜75%）。
2. 周りより明るい細長い塊を、白線の候補にします。
3. 車線は遠くの一点（消失点）に向かって収束します。向きが合わない候補（路面の反射、窓枠など）は捨てます。
4. 赤・緑など色の濃い光の反射は捨てます。**黄色い線（色相 44〜68°、彩度 0.4 超）は残します。**
   街灯に照らされたオレンジ色の草や縁石（色相 40°前後）は黄色に含めません。
5. 直近 1.5 秒のうち、**同じ位置に繰り返し出た線だけ**を採用します。一瞬だけの誤検出を抑えるためです。

処理は 1 フレームあたり数 ms です（ブラウザの疑似映像での計測）。

### 位置の基準（中央合わせ）

スマホはホルダーの位置や向きによって、画像の中心と車の中心がずれます。
**車が車線の中央にいるときに「中央合わせ」を押してください**（停車中に、同乗者の確認のもとで行ってください）。
基準は端末に保存されます。基準を設定するまでは、位置は表示しません（誤った数字を出さないため）。

### スマホの置き方に合わせる

映像の向きで、標準の設定を自動で切り替えます。

| 向き | 探索範囲（roi） | 消失点（vp） |
|---|---|---|
| 縦向き | 0.40〜0.535 | 0.53, 0.45 |
| 横向き | 0.45〜0.75 | 0.50, 0.46 |

横向きの値は、ダッシュボードに横向きで置いた状態のスクリーンショット（路面が 45〜79% に写る）に合わせています。
置き方が違うと、探索範囲がダッシュボードにかかったり、道路から外れたりします。
URL の末尾で調整できます（端末に保存され、向きに関係なく優先されます）。

```
https://（URL）/?roi=0.45,0.75&vp=0.50,0.46
```

横向きの映像は、同じ幅に広い範囲が写るため、白線が小さく見えます。長さなどの判定基準は、画像の短い辺に合わせて自動で縮めます。

- `roi`: 探索範囲（上端, 下端）。**画面の高さに対する比**。ダッシュボードの縁より上にする
- `vp` : 道路の消失点（幅, 高さに対する比）。真っ直ぐな道で、左右の線が集まる点
- `?reset=1` : 保存した設定を消す

画面には探索範囲が白い点線で表示されます。点線の下端が、ダッシュボードの縁に合うように調整してください。

## 標識認識をやめた理由

標識の「色と形」の候補を探す機能を作り、実機で試しましたが、外しました（コードは git の履歴 `300276a` までに残っています）。

- 色と形だけでは、標識と、店の看板・青い車・青いシートを区別できませんでした。
- 遠くの小さい標識を拾おうとすると、誤りも増えました。制限速度の数字は読めませんでした。
- このアプリの目的は事故の回避なので、**人の検出**を最優先にします。画面の「制限速度」の欄と「標識」の欄もなくしました。

## 動作確認の範囲

**確認した映像は 1 本（雨の夜、約 35 秒）だけです。** 昼間、晴天、黄色い線、高速道路、トンネルは確認していません。

- 走行中は、ほとんどのフレームで左右（または片側）の境界を検出しました。
- 交差点で停止している間は、「検出されず」になりました。
- 目視で 12 地点を確認し、8 地点は正しく、4 地点は一部が誤りでした。誤りは、**カーブ**と、**交差点に入る手前の濡れた路面**に集中しました。
- フロントガラスの水滴や、信号の赤い反射は、色と形で多くを除けました。ただし完全ではありません。

実機（iPhone Safari）では、処理が毎秒 9〜10 回で動くことを、画面の録画で確認しました。Android Chrome は未確認です。

## パソコンで動かす

```
npm test      # 単体テスト（Node.js 20 以上）
npm start     # http://localhost:8080 で配信
```

`localhost` は HTTPS でなくてもカメラが使えます。スマホの実機で試すときは、公開した HTTPS の URL を使います。

## 公開する（GitHub → Cloudflare Pages）

`main` ブランチに送ると、Cloudflare が自動で更新します。初回の設定は次のとおりです。

1. Cloudflare の管理画面で Workers & Pages → Create → Pages → Connect to Git を選び、リポジトリを選ぶ。
2. Framework preset: None / Build command: 空欄 / Build output directory: `/`
3. Save and Deploy を押す。

一般公開したくない場合は、URL を人に教えないのが最低限です。制限したい場合は Cloudflare Access（メール認証）を検討してください。

## 実機テスト（車線認識の確認項目）

iPhone は Safari、Android は Chrome で開いて確認します。**最初は停車中に、次に安全な場所で同乗者が画面を見て確認してください。**

| 確認項目 | 期待する結果 |
|---|---|
| 画面の白い点線（探索範囲） | 下端がダッシュボードの縁より上にあり、道路が範囲に入っている。違えば `?roi=` で調整 |
| 白線のある道路で走行 | 白線に水色の線が重なる。「車線」が「検出」になる |
| 白線のない場所（駐車場など） | 「検出されず」になる。「検出」のまま残らない |
| 車線の中央で「中央合わせ」→ 走行 | 位置が「中央」付近。左右に寄ると、寄った方向が表示される |
| 夜間・雨 | 検出が減る場合は、「検出されず」か「未確認」になる（誤った線が出続けないか） |
| カーブ | 線がずれる、または検出されなくなる（既知の弱点。どの程度か教えてください） |
| 速度・カメラ・常時点灯 | ステップ1と同じ（問題なし） |

## 既知の制限

- 黄色い線は、合成画像のテストでしか確認していません。実際の道路の黄色い線は、走行テストで確認が必要です。
- 夜間、街灯（オレンジ色）の下の黄色い線は、オレンジに写って黄色と判定されず、見落とすことがあります。
- 横向きの既定値は、スクリーンショット 1 枚から決めた値です。実際の走行で合わない場合は `?roi=` で調整してください。
- 消えかけた線、雪の道路は確認していません。
- カーブ、交差点、濡れた路面の強い反射で、誤検出や見落としが起きます。
- 自車の位置は、「中央合わせ」を正しく行うことが前提です。
- 画面ロックや他のアプリへの切り替えで、カメラと処理は止まります（ブラウザの仕様）。
- 認識結果は運転の判断に使わないでください。
